# 2026-10-14：无在线探针的实际 NR 模式

默认 RT 配置已切换为 `nr_direct`。在线运行不进行候选 MCS Monte Carlo 探针、独立 BLER 探针或概率缓存准入，不创建 BLER 查表文件，也不因某个 MCS 不可执行而自动回退到其他反馈后端。RT 几何、多小区干扰、预编码和实际 NR 编解码保持执行。

## 物理与控制语义

- 每次实际发送只执行一个 TB 的编码、加噪声、解码和 CRC/比特检查。重传使用原码字及已有 RV0/Chase 兼容性检查；资源不兼容时明确无 TB，不伪造新码字。
- MAC 通过现有链路质量、业务和 CSI 时效规则选择最终 MCS。旧参考模式的 16/27 等上限仍只用于显式参考模式，不能当成直接模式最终 MCS。重传保留原进程 MCS/table。
- SYS 继续提供并核对 NR 传输块大小，不调用 SYS 的 BLER/EESM 概率模型。不可执行的编码组合明确记录 `unsupported_nr_code_no_tb`。
- PHY 返回的 `bler` 是单次 TB 的 0/1 错误指示，不是预测概率。控制器使用已有实际 ACK/NACK 窗口及平滑统计；首个反馈前仍有测量初始化值。未产生 TB 的尝试不作为实际解码样本。
- `amc_probes=[]`、`bler_probe_samples=0`，AMC、BLER 和校准试验计数均为零。`amc_selection_target_met=None`，表示没有执行目标 BLER 准入校验，不能解释为目标已经满足。

这里去掉的是额外 Monte Carlo 试验，参考信号测量及已有导频资源开销继续保留。此改动没有新增论文算法，也没有实现新的在线 OLLA。当前 MAC 启发式的吞吐、BLER、可靠性和移动表现需重新验收，不能继承旧探针模式的承载结论。

## 使用

```bash
.venv-spark/bin/python experiments/run_rt_sys.py \
  --scene munich --cells 3 --ues 24 --slots 128 --seed 512 \
  --initial-queue-bytes 0 --ue-speed-mps 0 \
  --feedback-mode nr_direct --output outputs/my_nr_direct_run
```

专用入口不显式指定反馈模式时也使用 `nr_direct`。历史 `nr_tb_reference`、`nr_cached_reference`、`nr_bler_bank` 保留为显式校验/对照模式；选择这些模式仍可能执行探针。`nr_reference_screened.json` 也仍是旧参考模式的显式性能诊断配置。新模式无自动回退。

## 验证与数据

专项测试禁止概率探针和概率缓存调用，验证无 HARQ 上下文时只做一个实际 TB 试验，且同 seed/MCS/SINR 的 ACK 与旧实际参考路径一致；有 HARQ 上下文时验证同码字 Chase、资源不兼容零解码，以及重传 MCS 固定。全量本地回归为 256 passed、1 skipped、2 subtests，Spark 为 257 passed、2 subtests。

最终 GPU 数据位于 `outputs/rt_direct_20261014/final_mac/`：两地图各 3 小区/24 UE 的 8-slot 冷启动计时，以及空初始队列的 128-slot（64 ms）闭环。原始根目录的初版数据保留为诊断：它误用了参考 MCS 上限，不能作为最终版本验收。最终版本的计时、零探针计数、队列/HARQ/功率审计和仍存在的性能问题记录于相邻 `nr_direct_20261014.json`。

短运行证明执行路径与基础记账，不证明长期稳定、所有 UE 满足 QoS 或与旧模式吞吐等价。初版/旧版的源码指纹、配置快照与数据独立保存，原 `final_ran` 完整验收归档不修改。

最终计时夹具为 Street 约 7.26 秒、Munich 约 7.03 秒（含初始化与 CUDA 同步），旧实际参考夹具分别约 57.98 和 172.27 秒。MCS 选择语义已经变化，不能将这个运行时间差称为相同吞吐或相同错误率下的等价加速。

128-slot 空队列测试分别耗时约 43.16 和 46.29 秒，所有 UE 均有交付。Street 实际解码 1370 次、其中 NACK 109 次；Munich 实际解码 1049 次、NACK 193 次。该比例包含重传，不是独立首传 BLER。原码字资源不兼容产生的无 TB 尝试分别为 358 和 540 次，均明确记录，未伪造 ACK 或丢失队列载荷。这些数据说明链路自适应和重传资源安排仍需后续改进，不能宣称去掉探针后目标 BLER 或 URLLC 指标已通过。
