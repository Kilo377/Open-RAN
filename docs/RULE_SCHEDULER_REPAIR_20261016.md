# 切片与时延动作执行修复及定向短测

2026-10-16：修复 `slice_sla` 权重和 `latency_guard` 偏置在管理层归一化时被清空的问题。原 48 例长测的结构检查结果保留，但不能据此声称这两个参数曾完整生效。此次不重跑长测，也不要求规则算法带来优化收益。

## 修复

- 两类规则同步提交匹配的调度模式和提示，并在权限目录中声明提示字段；保留原 DU 各模式的计算方式。
- 切片权重仅在 `slice_aware` 消费，时延偏置仅在 `latency_aware` 消费。时延规则在恢复原切片模式时才提交该模式的权重，避免声称时延调度器消费切片权重。
- 首次干预前保存原调度模式，修复首次观测已紧急时无法正确恢复的问题。
- 执行配置报告增加实际调度提示，使停用恢复的模式和提示一致。
- 组合仲裁保留较低优先级请求以便重新启用；与最终模式不兼容的参数从执行集合移除，在仲裁轨迹记录 `inactive_scheduler_family:<mode>`。另一模式的默认空字典不取得切片权重的控制权。
- 回归断言覆盖最终消费者的具体值、多小区作用域、组合优先级、停用后重新仲裁及恢复，而不只检查模式名。
